วิธีดึง DTB จากกล่อง Android TV ผ่าน ADB (บน Linux Trixie)

Device Tree Blob (DTB) เป็นไฟล์สำคัญที่ใช้บอกระบบปฏิบัติการว่าฮาร์ดแวร์ในกล่องมีอะไรบ้าง บทความนี้จะแนะนำขั้นตอนการดึงไฟล์ DTB ออกมาจากกล่อง Android TV โดยใช้เครื่องมือ ADB บนระบบปฏิบัติการ Debian 13 (Trixie) ทั้งแบบต่อสาย USB และแบบไร้สายในวงแลนเดียวกัน

ข้อควรจำ: กล่อง Android TV ของคุณต้องเปิดใช้งาน USB Debugging (การแก้ไขข้อบกพร่อง USB) ในเมนูนักพัฒนาซอฟต์แวร์เรียบร้อยแล้ว

ขั้นตอนที่ 1: ติดตั้ง ADB บน Linux Trixie

เปิด Terminal บน Linux แล้วอัปเดตระบบพร้อมติดตั้งเครื่องมือ adb

sudo apt update && sudo apt install adb -y

ขั้นตอนที่ 2: เลือกวิธีเชื่อมต่อกับกล่อง Android TV

เลือกทำวิธีใดวิธีหนึ่ง (แบบ A หรือ แบบ B) ตามความสะดวกของคุณ:

แบบ A: เชื่อมต่อด้วยสาย USB (เสถียรที่สุด)

  1. ใช้สาย USB เชื่อมต่อระหว่างคอมพิวเตอร์ Linux กับกล่อง Android TV
  2. เช็คว่าระบบมองเห็นกล่องหรือไม่ โดยใช้คำสั่ง: 
    adb devices
  3. *ตรวจสอบหน้าจอทีวีเพื่อกด "ยอมรับ/Allow" ให้คอมพิวเตอร์เข้าถึงสิทธิ์ USB Debugging หากสำเร็จจะขึ้นสถานะ device ท้ายชื่ออุปกรณ์

แบบ B: เชื่อมต่อผ่านวงแลน (Wi-Fi / Ethernet)

  1. หาหมายเลข IP Address ของกล่อง Android TV จากเมนูตั้งค่าเครือข่ายในทีวี
  2. สั่งเชื่อมต่อผ่านระบบเน็ตเวิร์ก (เปลี่ยน 192.168.1.XXX เป็น IP จริงของกล่องคุณ): 
    adb connect 192.168.1.XXX:5555
  3. *ตรวจสอบหน้าจอทีวีเพื่อกด "ยอมรับ/Allow" ให้คอมพิวเตอร์เข้าถึงสิทธิ์การเชื่อมต่อเช่นกัน

ขั้นตอนที่ 3: ค้นหาและดึงไฟล์ DTB ออกมา

  1. ตรวจสอบพาร์ทิชันหรือตำแหน่งของ DTB

    โดยทั่วไปในระบบ Android TV ไฟล์ FDT (Flattened Device Tree) จะถูก map ไว้ที่ระบบไฟล์จำลอง ลองใช้คำสั่งตรวจสอบ:

    adb shell ls -l /sys/firmware/fdt
  2. ดึงไฟล์ DTB ออกมายังคอมพิวเตอร์ Linux

    หากเครื่องเจอไฟล์ในขั้นตอนก่อนหน้า ให้สั่งคัดลอกไฟล์มาเก็บไว้ในโฟลเดอร์ปัจจุบันของคอมพิวเตอร์ โดยตั้งชื่อไฟล์ใหม่ว่า extracted_dtb.dtb

    adb pull /sys/firmware/fdt ./extracted_dtb.dtb
⚠️ วิธีกู้คืนในกรณีที่หาไฟล์ /sys/firmware/fdt ไม่เจอ
ในกล่อง Android TV บางรุ่น (โดยเฉพาะรุ่นใหม่ๆ หรือ Android เวอร์ชันสูง) ระบบอาจจะไม่ได้ map ไฟล์ไว้ที่โครงสร้างโฟลเดอร์ดังกล่าว คุณจำเป็นต้องดึงจากพาร์ทิชัน (Partition) โดยตรงแทน ซึ่งทำได้ 2 วิธีดังนี้:

วิธีที่ 1: ดึงจาก dtb partition โดยตรง (แนะนำ)

1. ค้นหาพาร์ทิชันที่ชื่อว่า dtb ในเครื่องโดยเปิด adb shell เข้าไปดูบล็อกอุปกรณ์:

adb shell "ls -l /dev/block/by-name/ | grep -i dtb"

2. หากพบพาร์ทิชัน (เช่น บล็อกชี้ไปที่ /dev/block/mmcblk0pXX) ให้ใช้คำสั่ง dd เพื่อ Dump พาร์ทิชันนั้นออกมาไว้ในสโตเรจชั่วคราวของกล่อง:

adb shell "su -c 'dd if=/dev/block/by-name/dtb of=/data/local/tmp/dtb.img'"

3. ดึงไฟล์ที่ Dump ออกมามายังฝั่งคอมพิวเตอร์ Linux:

adb pull /data/local/tmp/dtb.img ./extracted_dtb.dtb

วิธีที่ 2: ดึงจาก boot partition (กรณีไม่มีแยกพาร์ทิชัน dtb)

หากไม่มีพาร์ทิชันแยก ส่วนใหญ่ไฟล์ DTB จะถูกรวม (Append) อยู่ท้ายไฟล์ Kernel ภายในพาร์ทิชัน boot

1. ทำการ Dump พาร์ทิชัน boot ออกมา:

adb shell "su -c 'dd if=/dev/block/by-name/boot of=/data/local/tmp/boot.img'"

2. ดึงไฟล์ boot.img กลับมายังคอมพิวเตอร์ Linux:

adb pull /data/local/tmp/boot.img ./boot.img

3. บน Linux Trixie ให้ติดตั้งเครื่องมือถอดแยกพาร์ทิชัน Android Boot และทำการแตกไฟล์ออกเพื่อหาไฟล์ dtb ด้านใน:

sudo apt install abootimg -y
abootimg -x boot.img

*ตรวจสอบไฟล์ที่ได้ในโฟลเดอร์ จะมีไฟล์ที่เป็นไฟล์ DTB ถูกแยกออกมาให้ใช้งาน

ขั้นตอนที่ 4: แปลงไฟล์เพื่อตรวจสอบความถูกต้อง (ทางเลือก)

คุณสามารถติดตั้งเครื่องมือ device-tree-compiler บน Linux Trixie เพื่อแปลงไฟล์โครงสร้างฮาร์ดแวร์จาก Binary (DTB) ให้กลับมาเป็น Text (DTS) เพื่อเปิดอ่านด้วย Text Editor ทั่วไปได้

sudo apt install device-tree-compiler -y
dtc -I dtb -O dts -o extracted_dtb.dts extracted_dtb.dtb

เมื่อรันเสร็จแล้ว คุณจะได้ไฟล์ extracted_dtb.dts ซึ่งเปิดดูรายละเอียดฮาร์ดแวร์ด้านในได้ทันที
